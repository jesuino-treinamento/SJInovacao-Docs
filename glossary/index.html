    📖 Glossário de Termos e Siglas¶

    Sobre este Glossário

    Este glossário centraliza os principais conceitos, padrões de arquitetura e tecnologias utilizados no desenvolvimento do ERP SJInovacao. O objetivo é facilitar o onboarding de novos desenvolvedores e alinhar a comunicação técnica com as áreas de negócio.

    🏗 Arquitetura e Design de Software¶

    Termo / Sigla Definição
    ADR (Architecture Decision Record) Documento que registra uma decisão arquitetural importante, incluindo o contexto, as alternativas consideradas e as consequências (positivas e negativas).
    Clean Architecture Padrão arquitetural que separa o código em camadas concêntricas (Domínio, Aplicação, Infraestrutura, Apresentação), garantindo que as regras de negócio não dependam de frameworks ou bancos de dados.
    CQRS (Command Query Responsibility Segregation) Padrão que separa as operações de leitura (Queries) das operações de escrita (Commands). No projeto, é implementado via MediatR.
    DDD (Domain-Driven Design) Abordagem de design de software focada em modelar o código de acordo com as regras e a linguagem do negócio (Linguagem Ubíqua).
    Feature Folders Estratégia de organização de pastas onde todo o código de uma funcionalidade (Command, Handler, Validator) fica na mesma pasta.
    Modular Monolith Arquitetura onde o sistema é implantado como um único processo, mas seu código interno é dividido em módulos fortemente isolados (Registry, UserAccess, Products, Sales, Customers, Finance).
    Shared Kernel Conceito de DDD onde um pequeno subconjunto do modelo de domínio (ex: Person, Document) é compartilhado entre múltiplos módulos (Bounded Contexts).
    SOA (Service-Oriented Architecture) Paradigma de arquitetura onde os serviços se comunicam via contratos bem definidos (ex: IPersonLookupService, IProductLookupService, ICustomerLookupService e IOutboxReader).

    🔐 Segurança e Autorização¶

    Termo / Sigla Definição
    BCrypt Algoritmo de hashing de senhas lento e adaptativo, projetado para resistir a ataques de força bruta. Utilizado para armazenar as senhas dos usuários.
    JWT (JSON Web Token) Padrão aberto (RFC 7519) para transmitir informações de autenticação de forma segura entre as partes. O token é stateless e assinado criptograficamente.
    RBAC (Role-Based Access Control) Controle de acesso baseado em permissões e papéis. No projeto, implementado através de Claims e do HybridPolicyProvider.
    PII (Personally Identifiable Information) Informações de Identificação Pessoal (ex: CPF, e-mail, telefone). Esses dados são mascarados na auditoria por questões de LGPD.
    Refresh Token Token de longa duração usado exclusivamente para obter um novo JWT (de curta duração) quando este expirar, sem requerer um novo login.

    🗄️ Banco de Dados e Performance¶

    Termo / Sigla Definição
    PostgreSQL Sistema de gerenciamento de banco de dados relacional de código aberto, escolhido por sua robustez e recursos avançados (JSONB, Trigram, etc.).
    GIN (Generalized Inverted Index) Tipo de índice do PostgreSQL otimizado para buscas textuais complexas, como as realizadas com a extensão pg_trgm.
    EF Core (Entity Framework Core) ORM (Object-Relational Mapper) da Microsoft para .NET, utilizado para mapear as entidades de domínio para as tabelas do PostgreSQL.
    Dapper Micro-ORM (Object-Relational Mapper) de alta performance. Utilizado no projeto para leituras de Lookup (Cross-Module) e para o Worker da Outbox, garantindo consultas em menos de 5ms.
    Eventual Consistency Modelo de consistência onde os dados (como a Materialized View) podem demorar alguns minutos para refletir a última escrita, em troca de ganhos massivos de performance na leitura.
    JSONB Formato de armazenamento binário de JSON no PostgreSQL. Utilizado na tabela AuditLogs para guardar os dados antigos e novos (OldValues/NewValues) de forma flexível.
    Materialized View Objeto do banco de dados que armazena fisicamente o resultado de uma query complexa. No projeto, otimiza a busca cruzada Users + Persons para ~22ms e a busca de catálogo para ~40ms.
    pg_trgm Extensão do PostgreSQL que fornece funções e operadores para determinar a similaridade de strings alfanuméricas. Utilizada no índice GIN para buscas textuais ultrarrápidas (ILIKE).
    TPT (Table-per-Type) Estratégia de herança do EF Core onde cada classe da hierarquia tem sua própria tabela. Foi descontinuada no projeto (ver ADR-005) em favor da Referência (PersonId).

    🧪 Qualidade e Testes¶

    Termo / Sigla Definição
    Mock (Moq) Objeto simulado utilizado em testes unitários para imitar o comportamento de dependências externas (ex: simular um banco de dados).
    Testcontainers Biblioteca que permite subir instâncias reais e efêmeras do PostgreSQL (via Docker) durante os testes de integração. Garante que os testes não sujem o banco local.
    Testes de Integração Testes que avaliam a comunicação entre múltiplos componentes (ex: API -> Handler -> Banco de Dados -> Worker).
    Testes Unitários Testes rápidos que avaliam uma única unidade de código (geralmente uma classe ou método) isoladamente.
    Fail-Fast Estratégia de validar o ambiente (ex: schema do banco de dados) no startup da aplicação. Se houver erro, a API não sobe, evitando falhas silenciosas em produção.

    📋 Metodologia e Processos¶

    Termo / Sigla Definição
    BPM (Business Process Management) Disciplina de gestão focada em modelar, otimizar e automatizar processos de negócio.
    BPMN (Business Process Model and Notation) Notação gráfica padrão para modelar processos de negócio (fluxos, gateways, eventos). Ver architecture/business-process.md.
    DoD (Definition of Done) Critérios de aceite que definem quando uma tarefa está oficialmente concluída (ex: "Build sem warnings e 156 testes verdes").
    KPI (Key Performance Indicator) Indicadores-chave de desempenho. Ex: Tempo de resposta da API (< 500ms) e Cobertura de testes (> 80%).
    Sprint Ciclo curto e fixo de desenvolvimento (geralmente de 1 a 2 semanas) no framework Ágil (Scrum). O projeto teve as Sprints S0 a S8.

    🧑‍💼 Recursos Humanos (US07)¶

    Termo / Sigla Definição
    Department (Departamento) Entidade do RH que representa uma área da empresa. Possui código único, nome e status (ativo/inativo). Não pode receber contratações se estiver inativo.
    Employee (Colaborador) Entidade raiz do RH que representa o vínculo empregatício de uma Person. Contém dados como RegistrationNumber, salário base e status (Hired, OnLeave, Terminated).
    RegistrationNumber (Matrícula) Código sequencial e único gerado automaticamente pelo PostgreSQL através de uma Sequence (employee_registration_seq), garantindo integridade sem depender do código C#.
    EmployeesOutboxConsumerService Worker (BackgroundService) do módulo Financeiro que monitora a employees_outbox. Ele projeta os dados do colaborador para a tabela employee_payroll_projections e garante a idempotência via ProcessedEvents.
    Payroll Projection (Projeção de Folha) Tabela no banco do Financeiro (employee_payroll_projections) que espelha os dados do colaborador (Nome, Matrícula, Salário). É utilizada futuramente para o cálculo da folha de pagamento, sem precisar acessar o banco do RH.

    🛒 Vendas e Controle de Estoque (US03)¶

    Termo / Sigla Definição
    Ledger de Estoque Livro-razão imutável (append-only) que registra cada movimentação de entrada e saída de um produto (StockMovement). É a fonte da verdade para auditoria, permitindo reconstruir o saldo a qualquer momento.
    Snapshot Fiscal Técnica de congelar os dados de um produto (Nome, SKU, Preço) no momento em que ele é adicionado a um pedido (OrderItem). Garante que alterações futuras no catálogo não afetem o histórico do pedido.
    Outbox Pattern (Transactional Outbox) Padrão de mensageria que garante a entrega de eventos. Em vez de publicar diretamente em um broker, o evento é gravado em uma tabela (IntegrationOutbox) na mesma transação de banco do negócio, e um processo separado o despacha.
    Overselling Problema de concorrência que ocorre quando o estoque de um produto fica negativo devido a vendas simultâneas que não foram devidamente sincronizadas. No projeto, é evitado com UPDATE atômico condicional.
    Soft Delete Estratégia de exclusão lógica onde um registro não é removido fisicamente do banco de dados, mas sim marcado como inativo (ex: IsActive = false). Preserva o histórico e a integridade referencial.
    Falha na Entrega (DeliveryFailed) Status atribuído a um pedido que saiu para rota, mas não pôde ser entregue (cliente ausente, recusa, etc). Dispara o fluxo de estorno e devolução de estoque.
    sales.order.delivery_failed Evento de integração emitido quando a entrega falha. É consumido pelos módulos Payments (para estorno) e Finance (para cancelamento do título).

    🧑‍💼 Clientes (US04)¶

    Termo / Sigla Definição
    Customer (Cliente) Perfil comercial vinculado a uma Person (Shared Kernel). Armazena dados de crédito, tipo de cliente (Varejo/Atacado) e status. Não possui FK física para o Registry.
    CustomerLookupService Contrato implementado pelo módulo Customers para fornecer dados do cliente (Nome, Documento, Status) ao módulo de Vendas via Dapper + View.
    vw_customers_lookup View de banco de dados que cruza a tabela Customers com a tabela Persons (do Registry) para fornecer dados de leitura performáticos ao módulo de Vendas.

    💰 Financeiro (US05)¶

    Termo / Sigla Definição
    AccountsReceivable (Conta a Receber) Título gerado automaticamente quando um pedido é pago. Contém o valor total, a data de vencimento (padrão 30 dias) e o status (Open, Paid, Overdue, Cancelled).
    Idempotência Garantia de que uma operação pode ser executada múltiplas vezes sem alterar o resultado. No projeto, é garantida pela tabela ProcessedEvents, que armazena o ID de cada evento já processado pelo Financeiro.
    ProcessedEvents Tabela do FinanceDbContext que armazena o EventId e o tipo de cada mensagem da Outbox que já foi processada com sucesso. Evita a geração de títulos duplicados em caso de reinício do Worker.
    OutboxProcessorService Worker (BackgroundService) do módulo de Vendas que lê a tabela IntegrationOutbox e despacha os eventos (marcando como ProcessedAt).
    FinanceOutboxConsumerService Worker (BackgroundService) do módulo Financeiro que consome os eventos da IntegrationOutbox (via IOutboxReader), gera as Contas a Receber e garante a idempotência.
    IOutboxReader Contrato (interface) definido no módulo de Vendas para permitir que o módulo Financeiro leia a IntegrationOutbox sem conhecer o SalesDbContext.
    Estorno (Refund) Ação de reverter uma transação financeira (PIX ou Cartão). No projeto, é disparada de forma assíncrona via API do Mercado Pago após uma falha na entrega.
    Cancelled (Recebível) Status de uma conta a receber que foi anulada antes do pagamento. Acontece quando a mercadoria volta para o depósito.

    💼 Termos de Negócio (ERP)¶

    Termo / Sigla Definição
    ERP (Enterprise Resource Planning) Sistema integrado de gestão empresarial que centraliza e automatiza processos de diferentes áreas (financeiro, estoque, vendas, RH, etc.).
    SKU (Stock Keeping Unit) Unidade de Manutenção de Estoque. É o código único que identifica um produto específico no catálogo (ex: tamanho, cor, modelo).
    Order (Pedido) Documento comercial que formaliza a intenção de compra de um ou mais produtos por um cliente. É a raiz do agregado no módulo de Vendas.
    OrderItem (Item do Pedido) Entidade filha que representa um produto específico dentro de um pedido, armazenando a quantidade e o snapshot de preço no momento da compra.
    StockMovement (Movimentação de Estoque) Registro imutável de qualquer entrada (Incoming), saída (Outgoing) ou ajuste (Adjustment) no estoque de um produto.
    StockBalance (Saldo de Estoque) Representação do saldo atual de um produto em estoque. É uma projeção otimizada, atualizada atomicamente a cada movimento.
    IntegrationOutbox Tabela de banco de dados que armazena eventos de integração pendentes de envio para outros módulos (ex: Financeiro), garantindo que nenhuma notificação seja perdida.
